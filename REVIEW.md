# Второй тест — реализация для ревью

База: `19cf6a7`. Ветка: `codex/second-test`. Резервная точка: локальный тег `codex/before-second-test-20261105`.
Публикация GitHub Pages, main, бот и его настройки не менялись.

## Архитектура

Исходный проект — один статический `index.html`, без сборки и серверной части. Первый тест содержит 7 вопросов с баллами 1–5; сумма 7–35 выбирает один из пяти диапазонов. Его HTML, inline CSS и inline JavaScript сохранены без изменений, за исключением нормализации переносов строк Git. Существующие ссылки: закрытый пост `https://t.me/c/1990809606/1061` и личный контакт `https://t.me/YanaShaturina`.

В `index.html` добавлены только общий выбор тестов, пустой контейнер нового теста и подключения файлов:

- `second-test-content.js`: дословные вопросы, ответы и библиотека результата из ТЗ.
- `second-test-engine.js`: чистая функция интерпретации десяти независимых осей. Не считает частоту букв. Выбирает до двух правил разных категорий в порядке приоритета. Для q8=A/q10=C разбор существующих свидетельств стоит перед планированием проверки новой гипотезы.
- `second-test-ui.js`: отдельное состояние, радиовыбор, явный следующий шаг, возврат,  подтверждение сброса только второго теста.
- `second-test.css`: стили, ограниченные контейнерами нового теста и меню; согласованная винная палитра `#89161C` из PDF пользователя, существующие формы и Telegram theme variables.
- `funnel-config.js`: подтверждённый адрес `https://t.me/Yana_Shaturina/60`, подпись «В этом посте» и согласованные два абзаца завершения воронки.

Все ответы живут только в памяти страницы. Перезагрузка начинает заново. Нет API ИИ, аналитики, хранения Telegram ID или персональных данных. Производственная страница не требует Node, npm или Playwright.

Для согласованного рекламного поста подготовлен прямой вход `https://t.me/YanaShaturina1_bot?startapp=second`. После публикации кода приложение распознаёт `start_param=second` в SDK или `tgWebAppStartParam=second` в URL и открывает второй тест. Параметр учитывается только при загрузке, поэтому возврат к выбору тестов работает. Обычный запуск по прежней кнопке остаётся общим меню. Код проверен локально для обоих способов передачи параметра; настройка Main Mini App у бота требует проверки в Telegram. До обновления GitHub Pages новая маршрутизация на действующей странице отсутствует.

Пост подготовлен с исходной картинкой, дословной подписью пользователя (451 символ без HTML-разметки) и inline URL-кнопкой «ПРОЙТИ ТЕСТ». В Telegram он не отправлен: нет авторизованной сессии и доступа к публикации ботом. Bot API создаёт сообщение в доступном боту чате, а не в личном «Избранном» пользователя; размещение там потребует пользовательской сессии/доступного inline-сценария. Сначала требуется разместить обновлённую версию Mini App, затем проверить запуск кнопкой.

## Как проверить

Открыть локальный preview, выбрать тест. Маршруты `#first` и `#second` работают и напрямую. Для возврата из первого теста использовать «Назад» браузера или Telegram BackButton; внутренние экраны первого теста не дополнены новыми кнопками. Переключение тестов в текущей странице сохраняет оба состояния независимо.

`node --test tests/engine.test.cjs` — структурная проверка всех 4^10 сочетаний и регрессии оригинала.

`npm install`, `npx playwright install chromium`, `npm run test:browser` — автономная браузерная проверка (тест сам запускает и закрывает локальный сервер). Браузер работает headless. Для сохранения снимков передать `QA_OUTPUT_DIR`, указывающий на существующую папку. В среде Codex использованы уже поставленные библиотеки и браузер в рабочей папке, без изменения настроек компьютера.

## Воронка

Пользователь предоставил PDF «Тест РАХУ-КЕТУ» с зашитой ссылкой на пост о себе и согласовал адаптированный текст. Новый тест завершается двумя абзацами и винной кнопкой «В этом посте», ведущей на `https://t.me/Yana_Shaturina/60`. Текст подходит после одного или двух тестов, не предполагает обязательного прохождения первого. Ссылка взята дословно из PDF, не заменена предположительным приватным адресом. Если после закрытия канала публичный адрес больше не работает, потребуется подтверждённая ссылка на тот же пост; доступа участника для проверки здесь нет.

По прямому указанию пользователя пояснение и открытая ссылка под CTA полностью удалены. В конце воронки — два абзаца курсивом, небольшая стрелка вниз и единственная винная кнопка «В ЭТОМ ПОСТЕ». Вызов Telegram происходит только по нажатию. При синхронном исключении SDK сохраняется стандартное поведение HTTPS-ссылки самой кнопки. При молчаливом отказе клиента дополнительного интерфейса нет, успешное открытие не заявляется. При удалении или неверном формате конфигурации интерфейс показывает честный статус вместо сломанной кнопки.

## Закрытый Telegram-канал

Официальные источники:

- https://core.telegram.org/bots/webapps — `openTelegramLink` принимает Telegram-ссылку; нет callback с подтверждением доступа/открытия. Начиная с Bot API 7.0 вызов не закрывает Mini App автоматически.
- https://core.telegram.org/api/links#message-links — формат приватного поста `https://t.me/c/<channel>/<id>` и `tg://privatepost?channel=<channel>&post=<id>`.

Текущий адрес соответствует документированному формату. `1990809606` — внутренний ID канала без Bot API-префикса `-100`, `1061` — ID сообщения. Формат не подтверждает существование или доступность конкретного сообщения. `tg://privatepost` не обходит членство и не является аргументом для `openTelegramLink`, который ожидает HTTPS Telegram-ссылку.

Рекомендуемое решение: сохранить текущую HTTPS-ссылку и вызов SDK по пользовательскому нажатию; после согласования добавить под старой кнопкой постоянную копируемую ссылку и короткую инструкцию. Для участника — открыть скопированную ссылку непосредственно в Telegram; если это работает, а Mini App — нет, исследовать конкретную версию клиента. Для неучастника — использовать только предоставленную владельцем действительную ссылку приглашения/существующий этап получения доступа. Сейчас приглашение неизвестно; автоматический возврат в канал не обещается. Не закрывать Mini App таймером после вызова: подтверждения открытия нет, пользователь может потерять результат. Не подменять рабочую кнопку новой схемой вслепую.

Для окончательной проверки нужны реальные iOS, Android и Desktop Telegram с записью версии клиента и двух состояний членства. Проверить ссылку сначала из сообщения Telegram, затем из Mini App, затем возврат к результату. Проверка в обычном браузере или mock SDK не доказывает успех этой цепочки.

## Известные ограничения исходного приложения

Старая кнопка поста не показывает запасной путь при молчаливом отказе Telegram. Её не меняли по требованию сохранить первый тест и не исправлять переход вслепую. Личная кнопка исходника не перехватывает исключения SDK. Никакие исправления этих двух обработчиков не заявлены. Автоматическая проверка не заменяет оценку редактором смысловой непротиворечивости всех текстовых сочетаний; утверждённые фрагменты сохранены дословно.
